# Deliverable D6 Walkthrough -- CD²F Consensus Engine

## Summary of Accomplishments

Deliverable D6 introduces the **Consensus-Driven Collaborative Decision Framework (CD²F)**, the core reasoning layer of SCOF. It evaluates the disparate, sometimes conflicting, mitigation recommendations generated by the individual specialist agents (Demand, Inventory, Supplier, Transportation) in a `ClaimBundle` and produces a single, reliable `DecisionRecord`. D6 delivers:

1. **CD²F Arbitration Logic ([services/consensus/src/arbitration.py](file:///d:/projects/SCOF_V1/SCOF/services/consensus/src/arbitration.py))**:
   - Implements Weighted Majority Voting algorithms based on agent profile confidence and historical accuracy.
   - Calculates the **Weighted Consensus Stability (WCS)** score to measure agreement among agent claims.

2. **Escalation Rules & Flow ([services/consensus/src/escalation.py](file:///d:/projects/SCOF_V1/SCOF/services/consensus/src/escalation.py))**:
   - Deterministically maps bundles to escalation tiers (`FAST_PATH`, `SLOW_PATH`, `HUMAN_ESCALATION`) based on WCS, severity, and partial bundle states.
   - Ensures any safety-critical failures or highly conflicting recommendations are escalated for human review.

3. **Human-in-the-Loop Calibration ([services/consensus/src/calibration.py](file:///d:/projects/SCOF_V1/SCOF/services/consensus/src/calibration.py))**:
   - Provides a mechanism to benchmark engine decisions against human expert baseline judgments using Cohen's Kappa score for reliability.
   - Implemented an automated judge calibration routine.

4. **Engine Orchestration ([services/consensus/src/engine.py](file:///d:/projects/SCOF_V1/SCOF/services/consensus/src/engine.py))**:
   - Main entry point `run_consensus` orchestrates normalizer, arbitration, escalation, and reasoning trail building into a unified pipeline.
   - Generates an immutable, auditable `DecisionRecord` containing the final recommendation, escalation rationale, and a reasoning trail.

5. **Infrastructure & Verification**:
   - Automated verification script [`scripts/verify_d6.py`](file:///d:/projects/SCOF_V1/SCOF/scripts/verify_d6.py) validating the CD²F engine against fixtures (agreement, disagreement, conflicting evidence, partial bundle) and running the calibration routine.
   - Added verification steps to [`Makefile`](file:///d:/projects/SCOF_V1/SCOF/Makefile).

### Manual Validation & Experimentation

To manually validate the consensus logic and experiment with CD²F's sensitivity, follow these steps:

#### 1. Modify the Profile Configuration
The CD²F engine relies on the domain profile for its escalation thresholds.
- Open `profiles/mvp-electronics/consensus.yaml`.
- Modify the `slow_path.min_confidence` threshold to `0.80`. (Note: Pydantic enforces that `slow_path.min_confidence` must remain strictly less than `fast_path.confidence_threshold`, which defaults to `0.85`).
- Run `make verify-d6` and observe the output. The "Disagreement Case" (which has a confidence of `0.53` and previously went to SLOW_PATH) now gets pushed to HUMAN_ESCALATION because it no longer meets the new strict `0.80` minimum. 

You will intentionally see the verification script print `[FAIL]` for this case and the Judge Calibration. **This is the expected behavior and demonstrates the engine's built-in safeguards working:**
  - **Routing Safeguard**: The engine correctly detects that the decision confidence (0.53) falls below your new strict minimum (0.80) and safely routes it to `HUMAN_ESCALATION`.
  - **Calibration Safeguard**: Because the engine now escalates decisions that human experts previously labeled as `SLOW_PATH`, the Cohen's Kappa score drops. The calibration suite catches this "drift" from human expectations and intentionally fails the run, preventing a faulty config update from being deployed without review.
- After testing, remember to revert `slow_path.min_confidence` back to `0.50` to restore a passing test suite.

#### 2. Alter a Test Fixture
The verification suite uses static JSON fixture files. You can edit these to simulate new edge cases.
- Open `services/consensus/fixtures/disagreement_case.json`.
- Change the `confidence` score of a specific agent's recommendation (e.g., `transportation`) to `0.99`.
- Run `make verify-d6` and observe if the escalation tier remains `SLOW_PATH` or if the high confidence pushes the WCS past the `FAST_PATH` threshold.

#### 3. Human-in-the-Loop Calibration Tuning
To see the Judge Calibration fail safely when the engine deviates from human expectations:
- Open `profiles/mvp-electronics/scenarios/calibration_set.json`.
- Change the `expected_escalation_tier` on the first scenario from `FAST_PATH` to `HUMAN_ESCALATION`.
- Run `make verify-d6`.
- The Calibration phase will report a lower Escalation Tier Kappa and fail, demonstrating that the engine's safeguards prevent deployment if it drifts too far from human expert baselines.
