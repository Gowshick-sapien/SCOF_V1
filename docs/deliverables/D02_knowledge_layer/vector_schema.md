# Deliverable D2 — PostgreSQL pgvector Schema Documentation

## 1. Overview
The Vector Store layer uses PostgreSQL with the `pgvector` extension to store decision logs, evidence snippets, embeddings, and model metadata. It supports vector similarity search for Graph RAG context augmentation, retrieving prior disruption decisions, and providing semantic context for SCOF agent reasoning.

---

## 2. Table Specifications

### Table: `scof.schema_version`
Tracks database DDL migrations.
```sql
CREATE TABLE IF NOT EXISTS scof.schema_version (
    version VARCHAR(50) PRIMARY KEY,
    description TEXT,
    applied_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

### Table: `scof.decision_records`
Stores structured decisions generated by Consensus Engine or seeded for historical decision retrieval.

```sql
CREATE TABLE IF NOT EXISTS scof.decision_records (
    id VARCHAR(50) PRIMARY KEY,
    scenario_id VARCHAR(50) REFERENCES scof.scenarios(scenario_id) ON DELETE SET NULL,
    run_id VARCHAR(50) REFERENCES scof.simulation_runs(run_id) ON DELETE SET NULL,
    disruption_id VARCHAR(50) REFERENCES scof.disruption_events(id) ON DELETE SET NULL,
    decision_type VARCHAR(50) NOT NULL, -- 'REROUTE', 'SUPPLIER_SWITCH', 'BUFFER_INCREASE', 'HOLD'
    recommendation TEXT NOT NULL,
    confidence NUMERIC(5,4) NOT NULL,
    priority VARCHAR(20) NOT NULL,
    impact_summary TEXT,
    created_by VARCHAR(50) NOT NULL DEFAULT 'SYSTEM', -- 'DemandAgent', 'SupplierAgent', 'ConsensusEngine'
    simulation_tick INT DEFAULT 0,
    outcome VARCHAR(50) DEFAULT 'PENDING', -- 'APPROVED', 'REJECTED', 'EXECUTED', 'FAILED'
    status VARCHAR(50) NOT NULL DEFAULT 'ACTIVE',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

### Table: `scof.evidence_snippets`
Stores evidence text snippets supporting agent claims and decision records.

```sql
CREATE TABLE IF NOT EXISTS scof.evidence_snippets (
    id VARCHAR(50) PRIMARY KEY,
    decision_id VARCHAR(50) REFERENCES scof.decision_records(id) ON DELETE CASCADE,
    source_type VARCHAR(50) NOT NULL, -- 'historical_data', 'model_output', 'graph_query', 'external_signal'
    source_id VARCHAR(100) NOT NULL,
    snippet_text TEXT NOT NULL,
    metadata_json JSONB,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

### Table: `scof.embeddings`
Stores vector representations and model metadata (`embedding_model`, `embedding_version`, `embedding_dimension`) for decisions, evidence snippets, and disruption scenarios.

```sql
CREATE TABLE IF NOT EXISTS scof.embeddings (
    id VARCHAR(50) PRIMARY KEY,
    entity_type VARCHAR(50) NOT NULL, -- 'decision', 'evidence', 'disruption_context'
    entity_id VARCHAR(50) NOT NULL,
    content_text TEXT NOT NULL,
    embedding_model VARCHAR(100) NOT NULL DEFAULT 'all-MiniLM-L6-v2',
    embedding_version VARCHAR(50) NOT NULL DEFAULT 'v1',
    embedding_dimension INT NOT NULL DEFAULT 384,
    embedding vector(384) NOT NULL,
    metadata_json JSONB,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

## 3. Indexing Strategy

To achieve fast cosine similarity search across high-dimensional vector spaces, an HNSW (Hierarchical Navigable Small World) vector index is built over the `embedding` column using `vector_cosine_ops`:

```sql
CREATE INDEX IF NOT EXISTS idx_embeddings_hnsw 
ON scof.embeddings 
USING hnsw (embedding vector_cosine_ops);

CREATE INDEX IF NOT EXISTS idx_embeddings_metadata 
ON scof.embeddings(entity_type, embedding_model, embedding_version);

CREATE INDEX IF NOT EXISTS idx_decisions_scenario 
ON scof.decision_records(scenario_id, decision_type, outcome);

CREATE INDEX IF NOT EXISTS idx_evidence_decision 
ON scof.evidence_snippets(decision_id);
```

## 4. Query Templates for Vector Search

### Metadata-Aware Cosine Similarity Search Template
```sql
SELECT 
    e.id,
    e.entity_type,
    e.entity_id,
    e.content_text,
    e.embedding_model,
    1 - (e.embedding <=> $query_vector::vector) AS similarity_score
FROM scof.embeddings e
WHERE e.entity_type = $target_type
  AND e.embedding_model = $active_model
ORDER BY e.embedding <=> $query_vector::vector
LIMIT $k_neighbors;
```

### Joined Decision & Evidence Retrieval Template
```sql
SELECT 
    d.id AS decision_id,
    d.decision_type,
    d.created_by,
    d.recommendation,
    d.confidence,
    d.outcome,
    ev.snippet_text AS evidence_snippet,
    1 - (e.embedding <=> $query_vector::vector) AS similarity_score
FROM scof.embeddings e
JOIN scof.decision_records d ON e.entity_id = d.id
LEFT JOIN scof.evidence_snippets ev ON d.id = ev.decision_id
WHERE e.entity_type = 'decision'
ORDER BY e.embedding <=> $query_vector::vector
LIMIT 5;
```
