# REST API Design

The API service acts as a thin routing/aggregation layer. It delegates to the Coordinator (port `8010`), Consensus Engine (port `8020`), and Observability Backend (port `8030`).

## Endpoints

### `/scenarios`
- **`POST /scenarios/trigger`**: Validates scenario, generates correlation context, and publishes a Kafka `disruption.triggered` event to be picked up asynchronously.
- **`POST /scenarios/replay`**: Looks up an original event payload by `event_id` in Redis and re-publishes it with a new `event_id` and `trace_id` for deterministic replay without violating idempotency.
- **`GET /scenarios`**: Lists available scenarios with pagination.
- **`GET /scenarios/{scenario_id}`**: Retrieves scenario details and associated disruption events.

### `/whatif`
- **`POST /whatif/run`**: Stores `RUNNING` status in Redis, publishes a Kafka `whatif.requested` event, and returns a `whatif_id` for polling.
- **`GET /whatif/{whatif_id}/result`**: Reads the final what-if result from Redis.
- **`GET /whatif/history`**: Lists recent what-if runs from Redis.

### `/dashboard`
- **`GET /dashboard/state`**: Aggregates entity counts, inventory health, active disruptions, recent decisions, and agent health into a single unified snapshot payload. Uses Redis for aggressive caching (TTL 5s) invalidated by decision completion.

### `/decisions`
- **`GET /decisions/{decision_id}/log`**: Proxies to Observability to extract the meeting log entries.
- **`GET /decisions/{decision_id}/confidence`**: Proxies to Observability to calculate per-agent confidence and recommendation tallies.
- **`GET /decisions/{decision_id}/trace`**: Proxies to Observability for full reasoning trail.
- **`GET /decisions`**: Lists recent decisions.

### `/evaluation`
- **`GET /evaluation/benchmark`**: Returns benchmark results from the D10 evaluation harness.
- **`GET /evaluation/calibration`**: Proxies to Observability for calibration history.

### `/chat`
- **`POST /chat/query`**: Accepts a natural language query and performs semantic retrieval over historical decisions and logs.

### `/profile`
- **`GET /profile/active`**: Returns the active Domain Profile metadata from `profile.yaml`.

## Correlation Context Specification

D08 is the public entry point for the platform. All requests generate or propagate a correlation context that flows through the entire service chain.

| Header | Generated By | Propagated To |
|---|---|---|
| `X-Request-ID` | D08 (per HTTP request, UUID) | All upstream HTTP calls, all Kafka events, all HTTP responses |
| `X-Trace-ID` | D08 (per orchestration, UUID) | D05, Kafka events, D07 reads |
| `X-Scenario-ID` | D08 (from request payload) | D05, Kafka events |
| `X-Profile-Version` | D08 (from loaded profile) | D05, Kafka events |

### Propagation Rules
1. **HTTP -> HTTP**: D08 includes all four headers on every call to D05 and D07.
2. **HTTP -> Kafka**: Headers are embedded in the event envelope's `correlation` object.
3. **Kafka -> HTTP**: Execution consumer extracts correlation from envelope and includes headers on D05 calls.
4. **D05 -> Kafka**: D05 extracts correlation from incoming request headers and embeds them in the `agents.activity` event envelope.
5. **HTTP responses**: `X-Request-ID` and `X-Trace-ID` are included in all D08 HTTP responses.
