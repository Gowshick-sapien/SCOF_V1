# State Isolation & Evidence Fabric Architecture

## 1. Executive Summary & Core Challenges

In a multi-agent decision support system operating across 30 enterprise domains, failing to isolate state leads to catastrophic failure modes:
1. **Benchmark Contamination:** If a simulation scenario mutates baseline inventory or financial tables, subsequent evaluation runs observe corrupted data, invalidating experimental rigor.
2. **Topological Degradation:** If runtime scenario branches write temporary or severed relationships directly into the 3.73M-node Neo4j graph, dirty edges accumulate and destroy baseline topology.
3. **Hallucinated Evidence:** If agent claims reference floating or unverified metrics, decisions cannot be audited or explained.

SCOF solves these challenges by enforcing a **Five-Tier State Hierarchy**, a **Tripartite State Isolation Model**, and an **Immutable Topology Overlay Engine with Deterministic Evidence Packs**.

---

## 2. The Five-Tier State Hierarchy

To eliminate ambiguity between historical data, current operational baselines, hypothetical simulations, agent opinions, and authoritative consensus, SCOF establishes five distinct state tiers:

```text
+===============================================================================+
| TIER 1: HISTORICAL FACT (Frozen Ground Truth)                                 |
| - Parquet files, canonical CSVs, historical transactions (D1)                 |
| - Sealed by cryptographic SHA-256 hashes in run_manifest.json                 |
| - Immutable: Write-once, read-forever                                         |
+===============================================================================+
                                       │
                                       ▼
+===============================================================================+
| TIER 2: BASELINE CURRENT STATE (Day-0 Operational Reality)                    |
| - Active PostgreSQL relational state & Day-0 balances                         |
| - Materialized Neo4j topology projection (3.73M nodes, 2.1M edges)            |
| - Clean operational reference for all unperturbed agent queries               |
| - Read-only during scenario simulations                                       |
+===============================================================================+
                                       │
                                       ▼
+===============================================================================+
| TIER 3: SCENARIO PROJECTION (Hypothetical World Sandbox)                      |
| - Ephemeral copy-on-write state overlays tagged with scenario_id              |
| - Forward-propagated disruptions and candidate interventions                  |
| - Isolated to the active simulation sandbox; never pollutes Tier 1 or 2       |
+===============================================================================+
                                       │
                                       ▼
+===============================================================================+
| TIER 4: AGENT RECOMMENDATION (Cognitive Claims & Proposals)                   |
| - Structured claims generated by specialist agents (Demand, Inventory, etc.)  |
| - Contains confidence score, proposed action, and evidence references         |
| - Explicitly treated as cognitive hypotheses, NOT state mutations             |
+===============================================================================+
                                       │
                                       ▼
+===============================================================================+
| TIER 5: CD2F DECISION (Arbitrated Consensus Choice)                           |
| - Consensus resolution approved by CD2F engine (WCS >= 0.70)                  |
| - Applied to Tier 3 Scenario State (and optionally routed for HITL ERP write) |
| - Formally recorded in D07 Verbatim Meeting Log and Reasoning Traces          |
+===============================================================================+
```

## 3. Tripartite State Isolation (ADR ADR 002)

The physical persistence architecture maps the five tiers into three strictly separated storage layers:

```text
+-------------------------------------------------------------------------------+
| LAYER 1: FROZEN GROUND TRUTH                                                  |
| Storage: Read-Only Filesystem (`datasets/master_enterprise_world/`)           |
| Provenance: generation_manifest.json with SHA-256 table digests               |
+-------------------------------------------------------------------------------+
                                       │ Loaded at Day 0
                                       ▼
+-------------------------------------------------------------------------------+
| LAYER 2: BASELINE OPERATIONAL STATE                                           |
| Storage: PostgreSQL (Production Schema) & Neo4j (Materialized Topology)       |
| Invariant: Read-only reference during simulation and evaluation               |
+-------------------------------------------------------------------------------+
                                       │
                  ┌────────────────────┴────────────────────┐
                  │ Isolated Fork                           │ Isolated Fork
                  ▼                                         ▼
+------------------------------------+   +------------------------------------+
| LAYER 3A: SCENARIO A RUNTIME       |   | LAYER 3B: SCENARIO B RUNTIME       |
| Storage: In-Memory Delta Overlay   |   | Storage: In-Memory Delta Overlay   |
| Scope: Scenario Alpha (Supplier X) |   | Scope: Scenario Beta (Port Y)      |
| State: Destroyed on completion     |   | State: Destroyed on completion     |
+------------------------------------+   +------------------------------------+
```

## 4. Immutable Neo4j Topology with Scenario Overlays (ADR ADR 006)

The Neo4j property graph contains **3,732,388 nodes and 2,104,188 edges**.

### The Graph Mutation Hazard
Modifying the graph directly during scenario simulations (e.g., deleting a `:CONNECTS_TO` edge to simulate a road closure) introduces critical flaws:
* Write locks in Neo4j block concurrent agent traversals.
* Graph rollbacks under transaction failure are expensive and leave orphaned nodes.
* Simultaneous scenarios cannot evaluate conflicting route perturbations.

### The Architectural Solution: In-Memory Topology Overlays
1. **Neo4j is 100% Read-Only:** During simulation runs, no Cypher `CREATE`, `SET`, or `DELETE` statement is ever executed against the database.
2. **Scenario Topology Overlay Dictionaries:** Any simulated network perturbation (e.g., closing Transport Lane `TL-0014` or disabling Chiller `AST-0082`) is recorded in the active `ScenarioContext` as an overlay set:
   ```python
   disabled_nodes: set[str] = {"AST-0082"}
   disabled_edges: set[str] = {"TL-0014"}
   edge_weight_modifiers: dict[str, float] = {"TL-0022": 2.5}  # 2.5x transit delay
   ```
3. **Query-Time Bounded Masking:** When the Twin or an agent executes a bounded graph traversal via MCP, the query passes the active scenario overlay to the query contract, filtering disabled entities in memory:
   ```cypher
   MATCH path = (origin:Facility)-[:CONNECTS_TO*1..3]->(dest:Facility)
   WHERE NONE(edge IN relationships(path) WHERE edge.lane_id IN $disabled_edges)
   RETURN path
   ```
4. **Complete Isolation:** Graph traversal remains fast, deterministic, non-blocking, and completely isolated across concurrent scenarios.

## 5. Deterministic Evidence Packs & Cryptographic Provenance

Every agent claim submitted to the orchestration kernel must be bound to a **Deterministic Evidence Pack**:

```json
{
  "evidence_pack_id": "evp-88219-4412",
  "scenario_id": "scen-disruption-sup-042",
  "sim_run_id": "run-0091",
  "timestamp": "2026-09-23T00:45:00Z",
  "provenance_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "state_snapshots": [
    {
      "entity_type": "inventory_position",
      "entity_id": "INV-DC01-SKU9912",
      "metric": "quantity_on_hand",
      "value": 140,
      "reorder_threshold": 500,
      "source_table": "inventory_positions"
    },
    {
      "entity_type": "purchase_order",
      "entity_id": "PO-009142",
      "metric": "days_delayed",
      "value": 14,
      "source_table": "purchase_orders"
    }
  ],
  "causal_trace": [
    "Supplier SUP-0042 lead-time blowout (+14d)",
    "PO-009142 delayed to DC-001",
    "Safety stock buffer depleted by Day 4",
    "Store stockout projected for SKU-9912 at 4 stores by Day 8"
  ]
}
```

### Invariants Guaranteed by Evidence Packs:
1. **Zero Hallucination:** Agents cannot fabricate numbers; claims without matching evidence pack hashes are rejected by the CD2F consensus engine.
2. **Audit Verifiability:** Regulators, operators, and benchmark harnesses can inspect the exact database snapshot and causal trace that justified any action.
3. **Observability Integration:** Evidence packs are stored verbatim in PostgreSQL and indexed in pgvector for semantic precedent search in D07.
